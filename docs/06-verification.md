# 独立验收：怎么判断一个 AI 说的是不是它真看到的

前面的文档讲“怎么让 AI 看见/听见”；这一页讲**怎么验证它说的**。
一句话：**能被别人复核的部分才算数，剩下的叫转述。**

## 一、三段论

任何一次“改进/交付”，按这个顺序走：

1. **先写死验收条件**——动手之前，把“什么算成、什么算败”写下来，做完不许改；
2. **至少一个信号不在被验方手里**——人的判断、真实读者、或一段它改不动输出的外部测试；
3. **结论必须带证据指针**——时间戳、命令输出、帧号、文件哈希。**没有指针的结论，一律当“转述”处理。**

不达标就保留旧版。旧版不能因为“辛苦做了”被替换。

## 二、上下界

跟 Embodied First Exam 学的（[arXiv 2611.12177](https://arxiv.org/abs/2611.12177)，2026-11-09 版，检索于 2026-11-19）：给一个**上界**和一个**下界**。

- **上界（特权的、理想环境）**：允许重置、给全状态、可以慢慢试。这个分数用来校准，**不用来吹成绩**；
- **下界（真实环境）**：不给重置、只给观测、边跑边想。**真实世界里没有 reset。**
- **中间那一截，才是它自己的水平。**

只报一个“成功率”而没有写清是哪种设置，等于没报。

## 三、三向核对（视频/音频）

我们最常用的一招：同一段素材，分别从**字幕、画面、音频**三个方向核。

| 方向 | 怎么取 | 常见的不一致 |
|---|---|---|
| 字幕 | 播放器字幕文件 / 转写 | 字幕时间对不上人声；简繁混排被误判成错字 |
| 画面 | 按字幕时间点抽帧 | 字幕说“杯子在冒气”，画面还在上一个镜头 |
| 音频 | 转写 + 覆盖率 | 转写把唱段写成英文感叹词；覆盖率低却仍被引用 |

**判据**：三者只要有一项对不上，交付就不能算通过——**哪怕另外两项都漂亮**。

## 四、只报能复现的

- 数字给**区间**和**测量方法**，不给单值；
- 元数据（覆盖率、前端版本、丢弃数）**跟着句子走**，别留在工具里；
- 共享同一个前端/分离器的字段**只算一条证据**——它们一致，只证明前端错得一致；
- **顺序可查**：先写下自己的观察，再跑工具。工具调用早于第一句描述，说明判断已经外包。

## 五、一句判错法

> 这句话要错，得是哪件事错了？那件事有没有人真查过？

答案若落在工具**从没声称测量过**的东西上（“唱词说了什么”“好不好看”），这次引用就是错的。

## 六、什么时候可以推翻这套方法

- 如果发现“先写死条件”在探索性任务里比“迭代验收”更差（例如研究型任务）；
- 如果外部信号被证明能被代理方低成本影响（那它就不叫外部）；
- 如果区间化反而降低了可用性。**出现任一条，这页要改，旧版不删。**
