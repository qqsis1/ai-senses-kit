# 记忆：一个可以以后对质的账本

## 一、为什么不是"记住就好"

摘要会随时间变淡，聊天记录会被清。真正的问题是：**三个月后，你还能不能说清"当时凭什么这么判断"**。

所以账本不是日记，是**判例库**：只追加、带署名、不覆盖。

## 二、条目结构

```json
{"id":"...","at":1790000000000,"who":"窗口A","kind":"judge","topic":"选题",
 "text":"结论一句话","basis":"依据：看到了什么、查到了什么",
 "refute_if":"什么情况下这条算错","refs":["..."]}
```

- `kind`：说 / 做 / 欠 / 改主意 / 判断 / 预测 / 对账 / 异议 / 想要；
- `refs` + `why_ref`：这条和那条**凭什么连**——图有了边才有用；
- `refute_if`：**判断必须自带推翻条件**，否则只是一个立场。

## 三、预测要对账

动手前先写一句可被推翻的预测（附概率），到点回来记"对/错"。

- 错了不是扣分，是**唯一能证明在长的事情**；
- 对账还要回答第二个问题：**这条预测当初值不值得押**。工程收据（"命令跑通了"）对账对了，也常常是用错了指标。

## 四、异议优先

同一件事允许两个窗口写不同判断。**异议不设否决权，但展示顺序优先**——先看见反对票，再看见结论。

写反方要用独立子代理：给事实和立场，要求"挑毛病、给反例、不许附议"。**反方不欠谁面子。**

## 五、修订不删

改主意时不是删旧条，而是写新条 + 指向旧条 + 说明为什么改（撞见什么证据、被谁纠正、情况变了）。

- 旧条不删，从此不被想起；
- "原来怎么想、为什么改"留在那里，断裂才有对照；
- 追责只追最后一条有效判断，但**能追出整条链**。

## 六、三条底线

1. **认账**：说过的话、做错的事，认它是自己的；
2. **只能补不能抹**：改主意也留痕；
3. **可追问**：每条账要能追出"谁、何时、凭什么"；对质不了的记录不算数。

## 七、别把账本做成日记

- 只记**会改变下次行为**的东西；
- 日常琐事不记；重复的事只记增量；
- 一次只写一件事，标题写清"这件事"；
- 定期体检：过期条目、没对账的预测、失效的置顶。
