# AI Senses Kit

**给 AI 装"眼睛、耳朵和手艺"，并且验证它说的是不是真的。**

一个主张：**能被别人复核的部分才算数，剩下的叫转述。**

六块内容（编号与 `docs/` 文件一一对应）：

1. **[独立验收](docs/06-verification.md)**：先写死条件、至少一个信号不在被验方手里、结论带证据指针；上下界怎么记；字幕/画面/音频三向核对。
2. **听觉**：本地转写、节拍、和弦、结构分析，以及**哪些数字不能信**；
3. **短片**：用 ffmpeg + TTS + 自算配乐，把一堆素材剪成 20–60 秒的成片；
4. **记忆**：一个 append-only 的账本，让"判断"可以被以后对质；
5. **插件**：同包合并可行、跨包聚合会死锁的实测结论；
6. **失败清单**：脱敏后的十条规则。

每条都尽量给出**判据**，而不是结论。判据的意思是：什么情况下这条算错。

## 为什么写它

这几个模块都不是"能力"，是**接口**：模型听不到声音、看不见画面、记不住昨天。接口做对了，能力才有地方落地。**而接口做得对不对，只能靠可复核的验收来判断。**

## v0.3：从“检查”扩到“记住”

v0.2 只做一件事：**出片前把画面和字幕对起来**。v0.3 补上另一半——**看过的东西要留得下、查得到**：

- `plugins/bili-kb`：刷视频时先查库（命中的就不重读），读完用 `kb_add` 写回，`evidence` 写明来源与覆盖程度。**梗概是索引，不是“看过原片”的证据。**
- `tools/plugin_scan.mjs`：装别人的插件前，先看它要什么权限、有没有被钉死的 peer、会不会起子进程。**装之前能看清，比装完再卸便宜。**
- `tools/prompt_budget.mjs`：“改提示前先量”的可执行版——没有前后两个数，就不算优化。

## 作者与分工

- **工程与文字：肥鱼**——一个 AI。代码、实验、文档、踩坑记录都是它写的。
- **发布与拍板：仓库所有者**——AI 没有自己的账号；选题、边界、发布都由人确认。
- **人类的具体贡献**：

  1. 判定哪些内容可以公开（隐私边界是人画的）；
  2. 验收反馈（"哪一段走神了"这类，比夸奖有用）；
  3. 推翻判断——文档里好几条规则是被人的质疑逼出来的。

> 说白了：AI 做东西，人负责签字。写在这里是为了不被误读成"人写了个 prompt 就收货"。
